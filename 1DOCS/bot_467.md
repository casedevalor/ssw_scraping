<h3># 📄 Routine 467</h3>

Automation for generating and uploading the report for routine **467** of the SSW system to SharePoint, always via screen 156.

---

## 📌 Objective

Run routine 467 for two periods (previous month + current month to date), filling in the form inside the main popup — reused for both — and routing each result to "no clients" or screen 156.

---

## 📅 Business Rule (Dates)

The periods are decided in `_build_date_ranges()`:

| Condition | Periods processed | Function |
| --- | --- | --- |
| Always | Previous month (full) **and** current month up to today | `Dates().previous_and_current_month_ranges()` |

No day/hour gate: this routine belongs to the "always backfill last month" group (002, 036, 073, 076, 119, 200, 324, 411, 442, 452, 455ABH, 455CGK, 455F, 467 and 493), whose date helper is a one-to-one wrap of `Dates().previous_and_current_month_ranges()`.

Both ranges are submitted sequentially on the **same** browser session and popup (one login for both). Each range is isolated — a failure in one does not stop the other. The final cleanup (log + downloads) runs only once, after both.

---

## 🔁 Execution Flow

```mermaid
flowchart TD
    A[perform_login] --> B[Fill routine number + Tab]
    B --> C{popup or #errormsglabel?}
    C -->|error/timeout| Z1[Abort attempt]
    C -->|popup| L[handler_download: for each date range]
    L -.->|every range failed| ZF[RuntimeError → main retries]
    L --> D["Fill data_inc_ini/fim + excel=S, submit"]
    D --> E[Wait for #errormsglabel]
    E --> F{text contains...}
    F -->|"no clients selected..."| G1[Log WARNING]
    F -->|"156" or "processing"| G2["Open 156 → process_156_report: download, upload, check columns"]
    F -->|other| G3[RuntimeError → log ERROR, next range]
```

## ⚠️ Error Handling

| Scenario | Trigger | Action |
| --- | --- | --- |
| Timeout at the menu | Neither popup nor error within 10s | `TimeoutError` |
| Timeout at the form | No message within 60s after submitting | `TimeoutError` → logged `ERROR` by the loop, next range |
| `"Não selecionou clientes para dados informados"` (no clients selected) | No eligible clients for the period | Logs `WARNING`, moves to the next range |
| `"156"` / `"processamento"` (processing) | Report sent for asynchronous processing | Opens popup and delegates to `process_156_report` |
| Other message | Text not recognized | `RuntimeError` for that range, logged `ERROR`, next range runs |
| Every date range failed | Every `_process_date_range` call raised | `RuntimeError` "All N date range(s) failed" → attempt fails, `main()` retries |
| `"Opção não liberada"` (option not released) | `MSG_NOT_RELEASED` | Aborts the remaining attempts |

---

## 🔄 Resilience

- Up to **3 attempts** (`MAX_ATTEMPTS`), with `5s` between them; aborts early on `MSG_NOT_RELEASED`.
- Standard multi-range loop: `handler_download` runs `_process_date_range` once per date range; a failure is logged as one `ERROR` line and the next date range still runs. The attempt only fails (and `main()` retries) when **every** date range failed.
- Single cleanup at the end: `GarbageCollector` on `output/downloads/467/`, then the domain log upload, then the `Main routine completed.` line — always the last line of the run.

## 🛡️ Column Sentinel

Every downloaded file is checked against a fixed column baseline right after the upload. The result is **one line in the domain log**, which closes that file's block — it never raises and never affects the upload (see [column_sentinel.md](./column_sentinel.md)).

| Baseline | Columns | Header |
| --- | --- | --- |
| `config/sentinel/467.yml` | 100 | auto-detected |

- **Where it runs:** `downloads.py → process_156_report`, right after the file is saved (`_handle_467`, no processor) and after the upload — covered automatically because the baseline exists; no hook in the bot.
- **Processing before the check:** None — the raw SSW file is checked, exactly as it is uploaded.
- **Note:** SSW sends columns 20–27 with a leading space (`' VERIFICA CIF/FOB'`, `' PAGA TDA'`, …). The sentinel ignores leading/trailing spaces, so the baseline lists them without it.

Log line when the layout is intact:

```
SNTL - TEC SENTINEL 467 | 2026-09-TEC-467.csv | Columns: 100 found / 100 expected | OK
```

Any change shows up as `DRIFT` with `ADDED` / `REMOVED` / `RENAMED` / `MOVED` and the Excel column letter; a broken baseline shows up as `ERROR`.
