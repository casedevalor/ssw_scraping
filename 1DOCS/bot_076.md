<h3># 📄 Routine 076</h3>

Automation for extracting, downloading, and uploading the report for routine **076** of the SSW system to SharePoint, per unit.

---

## 📌 Objective

Run routine 076 once for each configured unit, for each date range from `_build_date_ranges()`, routing to screen 156 whenever SSW puts the report into processing.

---

## 📅 Business Rule (Dates and Units)

| Condition | Periods processed | Function |
| --- | --- | --- |
| Always | Previous month (full) **and** current month up to today | `Dates().previous_and_current_month_ranges()` |

No day/hour gate: this routine belongs to the "always backfill last month" group (002, 036, 073, 076, 119, 200, 324, 411, 442, 452, 467 and 493), whose date helper is a one-to-one wrap of `Dates().previous_and_current_month_ranges()`. Each range is processed in isolation — a failure in one does not stop the other.

- Units processed: list in `config.yml` → `variables.bot_076.list_units` (e.g. `ANJ`, `RIC`, `COM`, ...), read via `settings.yaml_config.variables.bot_076.list_units`.
- Each (date range, unit) pair is isolated — a failure in one does not stop the others; the attempt only fails when **every** pair failed.

---

## 🔁 Execution Flow

```mermaid
flowchart TD
    A[perform_login] --> B[Fill routine number + Tab]
    B --> C{popup or #errormsglabel?}
    C -->|error/timeout| Z1[Abort attempt]
    C -->|popup| D[For each date range]
    D --> D1[For each unit in list_units]
    D1 -.->|every pair failed| ZF[RuntimeError → main retries]
    D1 --> E[Fill unit + dates + format E]
    E --> F[Click ►]
    F --> G{download or #errormsglabel?}
    G -->|timeout 60s| H1[Log ERROR, next unit]
    G -->|download| H2[Save .csv, upload to SharePoint, check columns]
    G -->|"156"/"processing"| H3[Open popup 156 → process_156_report (uploads, then checks columns)]
    G -->|other message| H4[Log WARNING, next unit]
```

**Particularity of this routine:** a single popup is opened once and reused for the whole unit list — unlike `bot_081.py`/`bot_019.py`, which open a fresh popup per unit.

## ⚠️ Error Handling

| Scenario | Trigger | Action |
| --- | --- | --- |
| Timeout at the menu | Neither popup nor error within 10s | `TimeoutError`, attempt fails |
| Error opening the routine | `#errormsglabel` visible after `Tab` | Closes modal, logs `ERROR`, `RuntimeError` |
| Timeout per pair | Neither download nor message within 60s | `TimeoutError` → logged `ERROR` by the loop, next pair |
| Download OK | `download` event | Saves, uploads, checks columns, logs `INFO` |
| `"156"` / `"processamento"` (processing) | Report sent for asynchronous processing | Opens popup and delegates to `process_156_report` |
| Other message | Text not recognized | Logs `WARNING`, next pair (not a failure) |
| Every (date range, unit) pair failed | Every `_process_unit_range` call raised | `RuntimeError` "All N (date range, unit) pair(s) failed" → attempt fails, `main()` retries |
| `"Opção não liberada"` (option not released) | `MSG_NOT_RELEASED` | Aborts the remaining attempts |

---

## 🔄 Resilience

- Up to **3 attempts** (`MAX_ATTEMPTS`), with `5s` between them.
- Standard multi-range loop: `handler_download` runs `_process_unit_range` once per (date range, unit) pair; a failure is logged as one `ERROR` line and the next (date range, unit) pair still runs. The attempt only fails (and `main()` retries) when **every** (date range, unit) pair failed.
- Aborts before the 3rd attempt if the message is `MSG_NOT_RELEASED`.
- Single cleanup at the end: `GarbageCollector` on `output/downloads/076/`, then the domain log upload, then the `Main routine completed.` line — always the last line of the run.

---

## 🛡️ Column Sentinel

Every downloaded file is checked against a fixed column baseline right after the upload. The result is **one line in the domain log**, which closes that file's block — it never raises and never affects the upload (see [column_sentinel.md](./column_sentinel.md)).

| Baseline | Columns | Header |
| --- | --- | --- |
| `config/sentinel/076.yml` | 29 | auto-detected |

- **Where it runs:** Direct download: `bot_076.py`, right after `download.save_as(...)`. Screen-156 path: `downloads.py → process_156_report`, which checks every routine that has a baseline.
- **Processing before the check:** None — the raw SSW file is checked, exactly as it is uploaded.
- **Note:** One file per unit **and** per month → the busiest routine in the log (~2 lines per unit per run).

Log line when the layout is intact:

```
SNTL - TEC SENTINEL 076 | 2026-09-TEC-ANJ-076.csv | Columns: 29 found / 29 expected | OK
```

Any change shows up as `DRIFT` with `ADDED` / `REMOVED` / `RENAMED` / `MOVED` and the Excel column letter; a broken baseline shows up as `ERROR`.
