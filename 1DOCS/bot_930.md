<h3># 📄 Routine 930</h3>

Automation for generating and uploading the report for routine **930** of the SSW system to SharePoint, always via screen 156 — the most frequently run routine in the daily flow (`WF_DAILY`).

---

## 📌 Objective

Run routine 930 for two specific days — yesterday and today (not a range) — routing each date to "no records" or screen 156.

---

## 📅 Business Rule (Dates)

The dates queried are decided in `_build_dates_to_process()`:

| Condition | Dates processed | Function |
| --- | --- | --- |
| Always | Yesterday **and** today (2 dates, processed separately) | `Dates().yesterday_and_today()` |

No hour gate since 2026-09-27 (user request): every run refreshes the last two days, so today stays up to date in each `WF_DAILY` block and yesterday is reprocessed. Before that, the bot queried today only, except at 1h/12h, when it queried the two days *before* today. Each date is isolated — a failure in one does not stop the other.

---

## 🔁 Execution Flow

```mermaid
flowchart TD
    A[perform_login] --> B[Fill routine number + Tab]
    B --> C{popup or #errormsglabel?}
    C -->|error/timeout| Z1[Abort attempt]
    C -->|popup| D[handler_download: for each date to process]
    D -.->|every date failed| ZF[RuntimeError → main retries]
    D --> E["Fill date (start = end)"]
    E --> F[Click ►]
    F --> G{#errormsglabel appears?}
    G -->|timeout 60s| H1[TimeoutError → log ERROR, next date]
    G -->|"no records found"| H2[Log WARNING, next date]
    G -->|"156"/"processing"| H3[Open popup 156 → process_156_report: download, check columns, upload]
    G -->|other message| H4[RuntimeError → log ERROR, next date]
```

There is also a `captcha_handler()` (reCAPTCHA via anticaptcha) kept in the code, but currently **disabled** — the call to `Recaptcha().solve_recaptcha(...)` is commented out, so the captcha flow is not exercised in practice.

## ⚠️ Error Handling

| Scenario | Trigger | Action |
| --- | --- | --- |
| Timeout at the menu | Neither popup nor error within 10s | `TimeoutError`, attempt fails |
| Popup didn't open | `task_popup` incomplete/errored | `RuntimeError` |
| Timeout per date | No message within 60s | `TimeoutError` → logged `ERROR` by the loop, next date |
| `"Nenhum registro encontrado"` (no records found) | No data for the date | Logs `WARNING`, moves on |
| `"156"` / `"processamento"` (processing) | Report sent for asynchronous processing | Opens popup and delegates to `process_156_report` |
| Other message | Text not recognized | Dismissed with OK, `RuntimeError` → logged `ERROR` by the loop, next date |
| Every date failed | Every `_process_date` call raised | `RuntimeError` "All N date(s) failed" → attempt fails, `main()` retries |
| `"Opção não liberada"` (option not released) | `MSG_NOT_RELEASED` | Aborts the remaining attempts |

---

## 🔄 Resilience

- Up to **3 attempts** (`MAX_ATTEMPTS`), with `5s` between them.
- Standard loop: `handler_download` runs `_process_date` once per date; a failure is logged as one `ERROR` line and the next date still runs. The attempt only fails (and `main()` retries) when **every** date failed.
- Aborts before the 3rd attempt if the message is `MSG_NOT_RELEASED`.
- Single cleanup at the end: domain log upload + `GarbageCollector` on `output/downloads/930/`.

---

## 🛡️ Column Sentinel

Every downloaded file is checked against a fixed column baseline before the upload. The result is **one line in the domain log** — the upload always proceeds (see [column_sentinel.md](./column_sentinel.md)).

| Baseline | Columns | Header |
| --- | --- | --- |
| `config/sentinel/930.yml` | 24 | auto-detected |

- **Where it runs:** `downloads.py → process_156_report`, right after the file is saved (`_handle_930`, no processor) and before the upload — covered automatically because the baseline exists; no hook in the bot.
- **Processing before the check:** None — the raw SSW file is checked, exactly as it is uploaded.
- **Note:** The first column header is `'0'` (not the usual `'1'` row counter). One file per date → 2 sentinel lines per run, and 930 runs in every `WF_DAILY` block.

Log line when the layout is intact:

```
INFO - TEC SENTINEL | 930 | 2026-09-27-TEC-930.csv | Columns: 24 found / 24 expected | OK
```

Any change shows up as `DRIFT` with `ADDED` / `REMOVED` / `RENAMED` / `MOVED` and the Excel column letter; a broken baseline shows up as `ERROR`.
